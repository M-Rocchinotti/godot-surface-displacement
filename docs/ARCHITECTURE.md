# Architecture

How GADS works, and why it is built this way. The README covers use, measured
cost and limitations; [RESEARCH.md](RESEARCH.md) the engine facts the design rests on.

## 1. The problem and the three layers

Godot 4.7 material shaders have vertex, fragment and light stages only: no tessellation, no mesh
shaders, no virtualized geometry. So "surfaces with height maps look like real geometry" is built
from three layers that each do what the engine allows:

| Layer | Where | What it gives | Code |
|---|---|---|---|
| Parallax occlusion mapping (POM) | every GADS material, any distance up to the fade | per-pixel relief at the height map's full resolution, occlusion between stones, shadows received on the relief (`LIGHT_VERTEX`), self-shadowing | `render/shaders/gads_core.gdshaderinc`, `gads_march.gdshaderinc`, `gads_surface.gdshaderinc` |
| Near-camera geometry | ground within 7.7 m of the camera (Ultra) | real vertices displaced by the height map: silhouettes, real depth (SSAO, intersections), coarse relief | `terrain/gads_displacement_field_3d.gd`, `render/shaders/gads_field.gdshaderinc` |
| Pebble scatter | gravel layers within ~8 m | loose stones as real little meshes | `terrain/gads_pebble_scatter_3d.gd`, `render/shaders/gads_pebble*.gdshader` |

Plus **baked displacement** for any mesh (`GADSMeshInstance3D`, section 9): the relief made
into real triangles in the editor by a native adaptive tessellator, for props whose silhouette,
shadows or collision POM cannot give. (The older offline Blender tool, `tools/bake_displaced_mesh.py`,
is not shipped.)

## 2. Conventions

- **Height** is the red channel, 1 = top, remapped by `height_remap` (x -> 0, y -> 1).
- **Relief in metres** along a *relief axis* `A`: `z = height_m * (h - height_center)`. `A` is the
  surface normal for UV mapping, world +Y for world-planar mapping, the projection axis (sign
  of the normal) for each triplanar plane. `height_center` is UE's "Displacement Center": 1 =
  relief below the surface (classic POM, walls), 0 = above it (ground under a field).
- **The march parameter is the relief height z**, not the ray distance. A view ray that hits the
  flat surface at `P` passes height `z` at `uv(z) = uv(P) + duv_dz * z` with
  `duv_dz = (gu.V, gv.V) * (N.A) / (N.V)`, where `gu`, `gv` are the gradients of u and v along
  the surface (1/m), `N` the surface normal and `V` the unit vector towards the camera. Moving
  `z` moves the ray point by `V * z * (N.A) / (N.V)`; that offset gives `LIGHT_VERTEX` and the
  optional depth. The same formula with `L` for `V` gives the self-shadow ray.
- The gradients come from the mapping: world-planar and triplanar ones are constant (the mapping
  is linear in the world position); for UV mapping they are the cotangent frame from
  screen-space derivatives of the position and the UVs (exact per triangle, no dependence on the
  mesh's tangent sign convention).
- Triplanar faces use a right-handed (image right, image up, outward axis) frame on every face, so
  normal maps read the same way on all six sides.

`tests/render_tests.gd` (`pom_matches_ray_traced_height_field`) checks all of this against a CPU
ray / height-field intersection written from these conventions, independently of the shader.

## 3. The surface shaders

```
variants/gads_<mapping>_<quality>[_depth].gdshader   (generated by tools/generate_variants.py)
  render_mode diffuse_burley, specular_schlick_ggx;
  #define GADS_MAPPING_UV | GADS_MAPPING_WORLD | GADS_MAPPING_TRIPLANAR
  #define GADS_POM, GADS_SELF_SHADOW, GADS_DEPTH_WRITE (as the name says)
  #include gads_surface.gdshaderinc   -> vertex(), fragment(), light()
      #include gads_core.gdshaderinc -> uniforms, mappings, self-shadow
          #include gads_common.gdshaderinc -> quality globals, fade, normal-map helper, Godot BRDF
          #include gads_march.gdshaderinc  -> the march (shared with the field)
```

Quality is switched by swapping a material's shader between the flat, POM and POM + self-shadow
variant of the same mapping (`GADSMaterials.set_quality`); all variants share one set of uniforms,
so parameters survive. Depth write is a separate, opt-in axis that survives the swaps. The
numbers that differ between presets (steps, fade, LOD bias, self-shadow steps and softness) are
global shader uniforms, so they change without recompiling anything.

### 3.1 The march (`gads_march`)

1. **Level of detail first.** The mip level is computed once, from the rasterized uv's
   derivatives, before any divergent control flow (`gads_march_lod`); every sample inside the loop is
   `textureLod` at that level. Implicit derivatives inside a data-dependent loop are undefined,
   and a missing mip chain makes every sample read the full-size map (the crater bug the research
   found). If the level is at or above `gads_pom_range.w`, the relief is below a pixel and the march
   is skipped.
2. **Adaptive linear search** from the top of the relief slab `(1 - c) * amp` down to its bottom
   `-c * amp`, with `mix(max_steps, min_steps, N.V) * pom_steps_scale * fade` steps.
3. **Bisection** of the bracketing interval (`gads_pom_steps.z` steps), then a final **secant** (a
   linear interpolation of ray-minus-relief in the last bracket, no extra sample).
4. **Distance fade**: `amp *= 1 - smoothstep(fade_start, fade_end, distance)`, and the step count
   with it. Beyond the fade end the shader does no march at all: plain normal mapping.

Final texture samples use `textureGrad` with the rasterized uv's derivatives (the hit uv jumps at
stone edges). The flat UV and world variants use `texture()`; the flat UV variant then matches ORMMaterial3D
exactly (render test).

### 3.2 Lighting

- `LIGHT_VERTEX = VERTEX + offset`: the engine substitutes it for the fragment position after the
  user fragment code, so shadow-map lookups and light falloff happen at the relief hit.
- **Self-shadowing** needs the light direction per light, which only `light()` has, and a custom
  `light()` replaces the engine's direct lighting. `gads_brdf` therefore repeats Godot 4.7.2's
  `light_compute()` for its default modes: Burley diffuse, Schlick-GGX specular with
  `V_GGX`, Schlick Fresnel with the engine's `f90`, and the multiple-scattering energy compensation
  `1 + f0 (1/E - 1)`. `E` comes from the engine's DFG look-up texture, which a shader cannot read;
  `tools/make_dfg_lut.py` recomputes it with the same Hammersley points and Smith-Schlick
  geometry term and stores it at the same texel centres as half floats (`render/textures/gads_dfg_lut.exr`,
  global `gads_dfg`). Two traps found by the parity test: the engine's `saturateHalf()` is not a
  [0, 1] clamp (only an FP16 cap), and a spatial shader without render modes gets *Lambert*
  diffuse - hence `render_mode diffuse_burley` in every variant. Area lights never reach
  `light()` (the engine shades them itself as long as the shader does not read the area
  built-ins). Not reproducible: the soft-light size term `A` (a few thousandths of N.L for lights
  with a size). Measured difference to the engine: 0.07 % at the 99th percentile.
- The self-shadow itself marches from the hit towards the light over the relief:
  hard (any relief above the ray) or contact-hardening (Tatarchuk 2006: the largest
  `(relief - ray) * k / distance`), with a 1 % bias, fading out towards `gads_shadow.y` metres.
  Directional lights always self-shadow; omni and spot lights when `gads_pom_steps.w` is 1
  (`GADSSettings.self_shadow_local_lights`, High and Ultra). For them `light()` gets `LIGHT` from
  the relief hit (`LIGHT_VERTEX`) towards the light, which is exactly the shadow ray: the march
  spans a few centimetres, over which the direction to a light metres away does not change.
  Each local light costs one march on every pixel it lights, so it is a setting.
  `render_tests.gd` (`local_light_self_shadow_matches_height_field`) checks an omni and a spot
  light against the CPU height-field shadow towards the light's position.

### 3.3 Opt-in depth write

`DEPTH` at the hit makes props intersect the relief. Its costs: the material loses early-Z, and
its depth pre-pass must run the fragment shader - the variant writes `VERTEX = VERTEX;` so the
engine does not draw its pre-pass with the shared flat-depth material. With the pre-pass on, the
colour pass keeps a fragment only if its depth is EQUAL to the pre-pass depth, and the two passes
are separately compiled shaders: they disagreed in the last bit on 1.3 % of pixels, which showed
as holes. The written depth is therefore rounded to 12 mantissa bits (0.25 mm at 2 m); a value that
lands exactly on a rounding step can still disagree (0 to 13 per million pixels measured).

## 4. `GADSDisplacementField3D`

### 4.1 Mesh and snapping

`L` rings of `N x N` quads (built once per (L, N) in `build_mesh`, cached while a field exists).
Ring 0 is a full square with spacing `s0`; ring `k` is a square annulus from `N/4` to `N/2` of its
own spacing `s0 * 2^k`. Per vertex: `UV` = integer lattice coordinates in units of `s0`, `UV2` =
(ring, seam flag). The mesh instance is moved to the camera snapped to multiples of `2^L * s0`,
so every ring's vertices always sit on the same world positions: nothing slides over the height
map when the camera moves (render test: zero height change near a walking camera).

### 4.2 Crack-free seams (geomorphing)

Towards its outer edge, ring `k` morphs: odd lattice vertices slide onto their lower even
neighbour (`lattice - odd * 2^k * m`, exact in lattice units) and the height is sampled one mip
coarser (`lod = log2(s0) + (k + m)`). At `m = 1` the ring's edge vertices have the same lattice
positions, the same LOD and therefore bit-identical heights as ring `k + 1`'s inner-edge vertices
at `m = 0`; the shared edges are identical and the rasterizer leaves no gaps. Edge vertices carry
flags that force `m = 1` (outer edge) and `m = 0` (inner edge). The morph ranges are chosen so
the distance-based morph agrees with the flags for every camera position inside a snap cell:
it ends before `R_k - delta` and starts after `sqrt(2) * (R_(k-1) + delta)` (`delta` = half the
snap); the logic tests check this for Ultra's grid and a dense one, and the validator warns when a
custom resolution makes it impossible. Because the fine ring is fully morphed where the grid's
snapping moves ring boundaries, the geometry does not pop either (render test: under 1 mm per
1 cm camera step in the morph band). No skirts are needed.

### 4.3 Heights, layers, the ground

`y = ground + lift + fade_field(d) * fade_pom(d) * sum_i w_i * height_m_i * h_i(xz, lod)`

- `ground` and the layer weights `w` come from an `GADSGroundBake` (or a flat plane at the node's
  height). The bake renders the ground group's meshes top-down in their own `World3D` with a
  capture shader that writes the world height as 16-bit fixed point split over two channels
  (exact in the half-float target), the layer index and coverage, and stores the captured image
  as it is: nothing runs per texel on the CPU (0.2-0.3 s for the demo's 90 x 90 m at 5 cm, most of it
  waiting for frames). `gads_ground.gdshaderinc`, shared by the field and the pebbles, decodes the
  4 x 4 texels around a point: a texel is displaceable when it and its four neighbours are
  covered and no neighbour differs by more than `step_limit` (0.8 x the texel size: slopes up to
  39 degrees are ground, kerbs and steps are not, whatever the texel size); uncovered texels take
  the mean height of the covered ones around them; heights, weights and the gradient normal are
  bilinear between texel centres; beyond the bake nothing is displaceable. `GADSGroundBake.sample()`
  is the same function on the CPU, and a render test checks the field's vertices against it.
- The vertices pass the normalised layer weights to the fragments (varyings), so the fragments
  do not decode the bake again.
- The field is drawn *on top of* the original ground: relief "up only", the geometry raised by
  `lift` (2 mm).
  Where no layer is displaceable, vertices dive `push_down` under the ground and the ground mesh
  hides them - no `discard`, so early-Z stays.
- Collision stays on the original ground.

### 4.4 Why the fragments still march

The geometry can only carry relief down to its vertex spacing (4 cm at Ultra; the denser grids
measured in 4.5 cost up to 2.2 ms more). A gravel's stones are smaller than
that, so the geometry alone shows soft lumps. Each field fragment therefore marches the full-resolution
relief over the whole slab along its true view ray, exactly like the ground material with
`height_center = 0`: the first hit of the ray with the height field does not depend on where the
proxy geometry was rasterized. The geometry adds what POM cannot: pixels the flat ground would
not cover (silhouettes), real depth for SSAO and for props, and the coarse relief. The relief is
measured from the ground, as the ground material measures it (`lift` raises only the proxy
geometry), so the field shades like the parallax ground it covers (render test: 0.15 % mean
difference inside the grid, 0.08 % in the last metre, zero beyond) and its edge is invisible.

The march's mip level and the texture gradients come from the footprint on the ground plane under
the proxy (the view ray's point at relief height 0), not from the proxy's own screen derivatives:
those jump at the proxy's bumps and silhouettes and would blur the relief there. A render test
checks the field's hits against the CPU ray tracer like the surfaces' (90th percentile 0.10 mm)
and its self-shadow against the CPU height-field shadow (99.8 %).

### 4.5 What the field costs, and why

In Forward+ the depth pre-pass runs a material's fragment shader when its vertex shader moves
the vertices (to get the normal-roughness buffer right), so the field's fragments march the relief
twice per frame, where the ground's POM runs once. Its triangles are small on screen (a few pixels,
thin at grazing angles), and the GPU shades 2 x 2 pixel quads, so part of that work is thrown away.
`tests/benchmark.gd --explore` measured the field on top of High's POM at 1080p on the GTX 1080:
1.4 ms for 3 rings of 96 quads at 4 cm, 1.5 ms for 4 x 96 at 4 cm, 1.9 ms for 3 x 128 at 3 cm,
2.1 ms for 4 x 160 at 2 cm and 3.6 ms for 4 x 256 at 1.5 cm. Ultra therefore uses the 3 x 96 grid
at 4 cm: it lifts cobbles and rocks, and the parallax (identical on and off the field) carries the
gravel.

## 5. `GADSPebbleScatter3D`

One `GPUParticles3D` whose particles are pebble slots in a window of cells that follows the camera
(Terrain3D's particle pattern, MIT). The particle shader places slot `i` of window cell `c` from a
hash of the cell's *world* coordinates and the slot, so pebbles stay put while the window moves
(render test: zero pixels change when the camera moves a metre). Density = layer weight x layer
density x preference for height-map valleys; pebbles rest on `max(relief, field proxy relief)` so
the proxy's depth never hides them; they shrink away between half the radius and the radius.
Rejected slots keep a zero transform instead of being deactivated: a deactivated particle is not
processed again until it is re-emitted and could not come back when the window moves.

The scatter copies the field's ground and layer parameters into its two materials only when the
field changed them (`GADSDisplacementField3D.get_parameters_version()`; the field itself sets a
parameter only when its value differs). Setting a texture parameter, even to the texture it
already holds, makes Godot's renderer free and rebuild the material's uniform set, which every
frame would be wasted work.

## 6. `GADSManager` and presets

`GADSSettings.create_preset()` defines Off / Low / Medium / High / Ultra; the node combines the
preset with four feature switches (a switch can remove a feature, never add one), writes the
globals, swaps the variants of every registered GADS material at runtime (materials entering the
tree later are registered through `SceneTree.node_added`), and sets the fields' ring count,
resolution and spacing and the scatters' density and radius. `GADSMaterials.materials_of()` finds
the materials a node draws with, wherever they sit: mesh surfaces, overrides and overlays and
their `next_pass` chains, MultiMesh and particle meshes, CSG shapes and GridMap mesh libraries.
`GADSSettings` emits `changed` from every setter, so edits to a Custom preset's resource apply at
the end of the frame like the node's own properties. In the editor it only writes the
globals, so saved materials keep their variant (editor check).

## 7. Resource lifetime

The field and scatter own their render objects as *internal* children (never saved, freed with
their parent), and so does a baked mesh its collision body; the field's static mesh cache is cleared when the last field leaves the tree; the
bake's capture viewport is freed after the capture. Shader globals hold plain values only. Every
test runner fails on "RID leaked", "ObjectDB instances leaked" or "resources still in use" at
exit.

## 8. How the tests avoid agreeing with themselves

- References are independent: a CPU ray / height-field intersection and a CPU height-field
  shadow written from the documented conventions, the height image's own mip data, analytic
  mesh heights, Godot's own lighting (the same material with the engine's `light_compute`), and
  ORMMaterial3D.
- Debug views write exact numbers (hit offset, world height, march cost, self-shadow factor) into
  a half-float viewport; the harness decodes them.
- Tests that check a direction use only the pixels where the right and the wrong answer differ
  (the shadow-edge test, the depth-write test), so a broken feature cannot pass on pixels that
  look the same either way.
- `tests/run_mutations.py` re-introduces known bugs one at a time (the list is in the README),
  each of which must turn its tests red.
- Baked geometry is checked against the height field it was baked from (random points inside the
  triangles, at their interpolated uv), closedness by welding the output and counting the
  triangles on every edge, and a baked mesh's render against the parallax render of the same
  material, with the wrong normal treatment rendered alongside so the test can tell them apart.

## 9. Baked displacement (`GADSMeshInstance3D`)

The relief of the GADS materials made into real geometry, offline, for any triangle mesh.

**Native tessellator** (`native/src/tess/`, engine-independent C++17, exposed as
`GADSTessellator` by a GDExtension built with godot-cpp; binaries for Linux and Windows x86_64 in
`addons/gads/native/bin/`):

- *Topology on welded positions.* Corners at the same position (UV seams, hard edges, surface
  borders) form one position group; edges are keyed by groups. Every corner of a group moves by
  the same vector (direction: the area-weighted normal of the group, or world +Y when every
  displaced surface is world-planar, matching the shaders' relief axis), so seams and hard edges
  cannot open, and a split creates one midpoint group shared by both sides.
- *Rivara longest-edge bisection.* A triangle is split across its longest edge after its
  neighbour across that edge has been brought to the same edge (longest-edge propagation, LEPP).
  The mesh stays conforming (no T-junctions) and angles stay at least half the source's (a
  plane's 45-45-90 triangles stay 45-45-90).
- *Error.* For each triangle: how far its own height field (sampled with the material's
  mapping and parameters, bilinear like the GPU) deviates from the plane through its displaced
  corners, in world metres. A min / max mip pyramid bounds it first, so flat regions are not
  scanned texel by texel. Triangles below the tolerance, or with edges under
  `min_edge_texels` texels, stay.
- *Budget.* Rounds refine the worst triangles first until every triangle meets the tolerance or
  the triangle budget is spent; the statistics report the error left.
- *Output.* Where refinement met the tolerance, vertices keep the full-resolution heights the
  error was measured against; where it stopped early (budget, smallest edge, deepest level),
  heights are filtered to each vertex's footprint (trilinear at the mip of its mean edge length)
  so coarse regions do not alias. Normals are rebuilt from the displaced faces,
  per cluster of source normals within `hard_angle` (hard edges stay hard); tangents by
  MikkTSpace in Godot's convention. `CUSTOM0` holds the rest position and the footprint's mip
  level, `CUSTOM1` the rest normal and the refinement level.
- Everything runs on worker threads (`parallel_for` over triangles and groups); results do not
  depend on the thread count (bake tests).

**Vector displacement.** A UV-mapped material can add a vector map: an XYZ offset per texel
(three height maps inside the tessellator, one per channel; 0..1 around 0.5 unless signed) times
`vector_displacement_m`. In tangent space the offset is `x * T + y * B + z * N`, where `N` is the
group's displacement direction, `T` the direction of +u and `B` of the texture's up (-v), both
from the area-weighted UV gradients of the source triangles around each corner, interpolated at
split midpoints and made orthonormal around `N` (the convention of OpenGL normal maps and of the
shaders' `gu` / `gv`); in object space it is the vector as it is, in the node's own units. The
error measures the distance from the displaced point (height and vector) to the plane through
the displaced corners' interpolation, and the mip-pyramid bound adds the vector's range on the
triangle plus how far its frame turns over it. Every corner of a position group moves by the
group's average offset, so UV seams, where the frames of the two sides differ, stay closed.

**Bake pipeline** (`geometry/gads_mesh_baker.gd`): resolves each surface's material, turns the
GADS parameters into the tessellator's displacement description, runs a render pass and an
optional coarser collision pass on a worker thread, builds LODs with `ImporterMesh.generate_lods`
(index buffers only, the vertices are shared) and the collision shape (trimesh or convex hull).

**Node** (`geometry/gads_mesh_instance_3d.gd`): `source_mesh` is never modified; `mesh` is the bake
or a mirror of the source. The bake is saved as `<cache_directory>/<name>_<key>.mesh`, where the
key hashes everything that shapes it: the source (path and file times for imported assets,
contents for built-in resources), each surface's displacement parameters and height map, the
transform where it matters (the basis always, since the tolerance is in metres; the origin for
world and triplanar mappings), the settings and the pipeline and library versions. The scene
refers to the file; the same inputs bake once; a changed input makes the bake stale (inspector,
configuration warning, validator). The collision body is an internal child, rebuilt from the
saved shape when the scene loads.

**Shaders on a baked mesh.** The node sets the instance uniform `gads_baked`. The surface shaders
then skip the march (the geometry carries the relief), map textures at the rest position from
`CUSTOM0` (so they do not stretch over the displaced slopes, and world-planar textures stay put)
and pick triplanar weights from the rest normal. The normal map needs care: it encodes the
relief's full slope, and the geometry already carries the slope down to the triangle size.
Applying the normal map on top of the geometry's normal tilts the flanks twice. So the shaders
take only the part of the normal map finer than the triangles: the normal map sampled at the
footprint's mip level (`CUSTOM0.w`, what the geometry carries) is rotated back to +Z and the
same rotation is applied to the full-resolution sample (Reoriented Normal Mapping run
backwards), and that detail goes on the geometry's normal and tangents. Where triangles are
smaller than a pixel the two samples agree and the geometry alone shades; without a normal map
the detail is flat and the geometry shades too.

**Clusters.** With `cluster_triangles` the tessellator's output is split into spatial clusters
after refinement: the triangles' centroids are split at the median along the longest axis of
their bounding box until a part holds at most the target (a total order on ties keeps it
deterministic), all surfaces together, and each cluster re-indexes its vertices. Every cluster
gets its own LODs from `ImporterMesh.generate_lods`, which locks open borders, so neighbouring
clusters at different LODs still share their border vertices. The node draws the first cluster
itself and the others with internal children that copy its draw settings (checked each frame
while clusters exist). Godot measures a visibility range from each instance's own AABB centre,
so with a `geometry_range` every cluster would switch to parallax at a different moment; instead
each cluster's rendering instance gets the fallback's instance as its visibility parent (set on
the RenderingServer: a node's `visibility_parent` would be inherited by its whole subtree, the
fallback included), and they all show exactly while the fallback is hidden by its range.

**Runtime (view-dependent) tessellation.** The same tessellator with a view position: a
triangle's tolerance becomes `max(max_error, pixel_error * distance / focal_px)`, where distance
is from the eye to the triangle's bounding sphere and `focal_px` the pixels per radian of the
camera; no edge is split below `min_edge_pixels` on screen, and refinement takes the largest
error relative to its tolerance first, so the budget goes where the error shows most. Without a
view the tolerance is `max_error` everywhere and the output is unchanged. `GADSMeshInstance3D`
runs it in the background when the camera has moved a quarter of its distance (or zoomed) and
swaps the mesh when it is ready; heights where refinement stopped early are footprint-filtered as
in a bake, so far, coarse triangles do not alias.

## 10. Runtime deformation (`GADSDeformationField`)

A depth map over a square window of world XZ: `resolution` texels of `size_m / resolution`,
addressed toroidally (a world texel `c` lives at `c mod resolution`), so when the window follows
its node only the rows and columns that left it are cleared and every mark keeps its texel. Each
texel holds two floats: the depth when stamped and the stamp time. Recovery is not simulated:
the shaders and `get_depth()` both compute `depth - recovery_rate * (now - stamp time)` (clamped
at 0), so marks refill without any per-frame work and a rate set later applies to the time
already passed. Painting (`stamp`, `stroke`, `stamp_image`) runs on the CPU over the texels within
reach, combining by DEEPEN (max), ADD or SET; the map is uploaded (RGF) once per frame in which it
changed.

Three shader globals carry it: the texture, the window (origin, side, deepest depth: 0 turns it
off) and the clock (now, recovery). `gads_deformation(xz)` samples it bilinearly with wrapped
`texelFetch` (no sampler wrap mode does modulo addressing). The displacement field subtracts it
from the relief in its vertex shader and starts its march below the surface by `max_depth`; the
surface shaders shift the parallax plane down by the depth (world-planar: everywhere; triplanar:
the top plane; UV: scaled by how much the surface faces up).

## 11. `GADSTerrain3D`

**Grid and chunks.** The size is rounded to whole chunks of `chunk_quads` quads at
`vertex_spacing`; heights are the heightmap, bilinear, at each vertex. Each chunk is one
`ArrayMesh` surface whose LODs are index buffers over the same vertices at strides 2, 4, 8...
The LOD key Godot compares against its screen-space threshold is the LOD's largest vertical
deviation from the full grid (computed per chunk), so the engine picks the coarsest LOD whose
error stays under `threshold_pixels`. Neighbours at different LODs interpolate the same border
heights at different strides; each is within its LOD's error of them, so the gap between them
is under twice the largest error, and skirts of that depth hang from every border. The grid's
quads split along the (1, 0)-(0, 1) diagonal, the same triangulation the HeightMapShape3D of
Jolt and Godot Physics uses, so collision is the drawn surface.

**Layers.** Weights for the second and third layer per vertex (splat map, or smoothstep rules
on slope and height) go to vertex colour R and G, which the layered material reads as its masks;
`GADSMaterials.combine_layers()` copies the layer materials' textures, depths and texture sizes
into one layered material.

**Detail field.** The terrain gives its `GADSDisplacementField3D` ground data made with
`GADSGroundBake.from_arrays()` instead of a capture: texel centres sit on the vertices (half the
spacing apart by default), where the field's bilinear heights equal the triangles; in between,
a texel cell that a quad's diagonal crosses can differ by up to an eighth of the quad's crease
`|h00 + h11 - h10 - h01|`, so the field is lifted by the largest crease on ground it displaces.

**Streaming.** With `stream_radius`, nothing is computed for the whole terrain: heights and
weights are read from the heightmap per vertex when a chunk is built. Chunks within the radius
are built on worker threads (four at a time, nearest first; the build function reads only
immutable data and returns arrays), added on the main thread (two per frame), and freed beyond
1.25 x the radius plus a chunk. Each has its own HeightMapShape3D. The field's ground data is a
window around the camera, rebuilt on a worker thread when the camera has moved a quarter of it.

## 12. Renderers

The shaders are written for Forward+ and run unchanged on Mobile. On Compatibility (OpenGL 3.3 /
ES 3.0) two things differ: GLSL 1.30+ forbids indexing a sampler array with a loop variable, so
the field and pebble shaders select their layer textures by constant index there
(`GADS_LAYER_LOD` / `GADS_LAYER_GRAD`, `CURRENT_RENDERER`); and clip-space depth is -1..1, so
the depth write maps it to 0..1. The runtime ground capture is not possible on Compatibility: the
renderer writes through an approximate sRGB encode / decode that does not return the 16-bit
height code, so a field there needs a bake saved from the editor and stays off without one.
`tests/renderer_tests.gd` checks every variant, the depth write, deformation and the demo scenes
on both renderers.

## 13. Procedural height maps (`GADSProcedural`)

`native/src/proc/height_gen.cpp` makes every pattern periodic on the unit tile, so the maps tile
by construction: gradient noise hashes its lattice corners modulo the octave's period (each
octave a whole multiple of the first, octaves beyond half the resolution dropped); Voronoi cells
(stones, cracks) jitter points on a wrapped grid and measure the exact distance to the nearest
cell border (the bisector with each neighbour of the nearest point); bricks use an even number
of rows and a whole number of bricks per row, waves integer wave vectors, ripples and craters
distances on the torus, faded out before half a tile. Domain warp offsets the coordinates by
periodic noise, so warped patterns tile too. Each field is normalised to 0..1. The derived maps
wrap at the borders as well: normals by central differences in metres (OpenGL convention, as the
shaders read them), occlusion as 1 - sin of the horizon elevation averaged over 8 directions
(12 samples each, denser near the texel), curvature as the height minus two box blurs. Rows run
in parallel; the results do not depend on the thread count. `tests/run_logic_tests.gd` checks
the range, the seams (the wrap-around boundary against its neighbours), determinism and the
derived maps on known shapes.
